**Seeding without a browser:** create clients via `ClientService`. /authorize is built in parallel by 02-13, so do not depend on it.
Obtain codes by seeding a user + session (storage ports) and calling the pure `anvil_core::service::authorize::build_code` helper (02-07),
then `GrantRepo::create_code`. Keep the plaintext code for the exchange. The full browser path is covered by conformance (02-19) and e2e (02-20).
private_key_jwt tests build assertions with an ES256/RS256 key generated in the test (anvil-jose `SigningKey` or aws-lc-rs) and register its
public JWK inline in the client's jwks.

**HTTP details:** /token accepts only `application/x-www-form-urlencoded` POST (else invalid_request). Duplicate parameters → invalid_request.
The Authorization header is passed raw into `ClientAuthInput.basic`. Responses: 200 JSON + `Cache-Control: no-store` + `Pragma: no-cache`.
/userinfo: GET with a header, POST with a header, POST with an `access_token` form field (RFC 6750 §2.2). `access_token` in the query → 401
(and so is header + body together → 400 invalid_request). Response `application/json`. CORS (`public_cors`) on both. The browser CSRF layer does not apply.
