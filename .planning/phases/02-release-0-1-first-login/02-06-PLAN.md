- `rotate_refresh` in one transaction. First the conditional `UPDATE refresh_token … WHERE consumed_at IS NULL AND expires_at>$now AND family_id IN (SELECT id FROM token_family WHERE revoked_at IS NULL AND absolute_expires_at>$now) RETURNING family_id`. Concurrent rotations serialise on the row lock, and losers see 0 rows. On 0 rows, `SELECT consumed_at FROM refresh_token WHERE …`. If it is consumed → `UPDATE token_family SET revoked_at=$now, revoked_reason='refresh_reuse' WHERE id=… AND revoked_at IS NULL` → ReuseDetected. Otherwise → NotFound.
