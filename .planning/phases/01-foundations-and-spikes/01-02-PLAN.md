<task type="auto" tdd="true">
  <name>Task 2: Dependency-rule checker with negative self-test</name>
  <files>scripts/check-deps.sh</files>
  <behavior>
    - Clean tree: exit 0, prints "dependency rules OK"
    - Self-test case A: anvil-core gains normal dep `tokio` → checker exits non-zero
    - Self-test case B: anvil-web gains NORMAL dep `anvil-storage-sqlite` → checker exits non-zero
    - Self-test case C: anvil-web gains DEV dep `anvil-storage-sqlite` → checker exits 0 (dev deps are allowed)
    - Self-test case D: anvil-storage-sqlite gains normal dep `anvil-web` → checker exits non-zero
    - `--self-test` exits 0 only if A, B, D fail and C passes
  </behavior>
  <action>
Implement per 01-RESEARCH.md Pattern 15 (bash, `set -euo pipefail`, executable), adapted to the crate-layout
decision. Use per-package resolution, never `cargo metadata` (Pitfall 8):
- `deps_of crate`: `cargo tree --locked -q -p "$crate" -e normal,build --target all --prefix none --format '{p}' | awk '{print $1}' | sort -u`
  (normal+build edges only, so dev-dependencies are ignored by construction — this is the "normal deps only" rule).
- `direct_of crate`: `cargo tree --locked -q -p "$crate" -e normal --depth 1 --prefix none --format '{p}' | awk 'NR>1{print $1}' | sort -u`.
Rules (each violation prints `RULE VIOLATION: <crate> ...` and sets fail=1; script exits $fail):
- anvil-core direct deps allowlist: anvil-jose serde serde_json time uuid url thiserror async-trait.
- anvil-core transitive forbid: tokio mio hyper axum tower reqwest sqlx sqlx-core libsqlite3-sys tokio-postgres,
  anvil-storage, anvil-storage-sqlite, anvil-storage-postgres, anvil-web, anvil-cache, anvil-mail.
- anvil-storage forbid: sqlx sqlx-core anvil-storage-sqlite anvil-storage-postgres anvil-web.
- anvil-storage-sqlite / anvil-storage-postgres forbid: anvil-web, and each other.
- anvil-web, anvil-jose, anvil-cache, anvil-mail forbid: anvil-storage-sqlite anvil-storage-postgres sqlx sqlx-core
  (normal graph only; only anvilid knows concrete implementations).
On success print "dependency rules OK".

`--self-test`: copy the workspace into `mktemp -d` (rsync or `tar --exclude=./target --exclude=./.git`), cd
there, and for each case A–D: restore a pristine copy of the manifests + Cargo.lock, apply the mutation with
`cargo add --offline` (A: `-p anvil-core tokio`; B: `-p anvil-web anvil-storage-sqlite --path crates/anvil-storage-sqlite`;
C: same with `--dev`; D: `-p anvil-storage-sqlite anvil-web --path crates/anvil-web`), run the checker on that copy
(`CARGO_TARGET_DIR` pointing into the temp dir is not needed — cargo tree does not compile), and assert the
expected exit status. Offline works because every crate involved is already in Cargo.lock. Print one PASS/FAIL
line per case; clean up the temp dir with a trap. If `cargo add` needs to modify the lock in a way that requires
network, fall back to editing the copied Cargo.toml with sed and `cargo tree --offline` (document which in SUMMARY).
  </action>
  <verify>
    <automated>cd /home/lspecian/Development/anvil-id && scripts/check-deps.sh && scripts/check-deps.sh --self-test</automated>
  </verify>
