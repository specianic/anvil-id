    - GET /healthz → 200 with body `ok`
    - GET /authorize, POST /token, GET /jwks → 501 with JSON `{"error":"not_implemented","error_description":"..."}` (negative: never 200)
    - GET /assets/anvil.css → 200, content-type text/css, ETag = quoted lowercase hex SHA-256 of the file bytes; If-None-Match with that ETag → 304
    - GET /assets/does-not-exist.css → 404; GET /assets/../Cargo.toml style traversal → 404

  body/form/button basics). No external URLs (UI-01 direction).
- `discovery.rs`: `#[derive(Serialize)] struct ProviderMetadata` with issuer, authorization_endpoint, token_endpoint,
  jwks_uri, response_types_supported ["code"], subject_types_supported ["public"],
  id_token_signing_alg_values_supported ["ES256"], code_challenge_methods_supported ["S256"],
  grant_types_supported ["authorization_code"], token_endpoint_auth_methods_supported ["client_secret_basic"],
  scopes_supported ["openid"]. Build it once from `WebConfig.issuer` (trim the trailing slash; join endpoint
  paths onto the issuer path). Only advertise values the M1 design actually targets; document on the struct that
  M0 advertises endpoints that return 501 until M1 implements them (01-RESEARCH.md Open Question 6).

  "error_description":"<endpoint> is not implemented in this build (M0)"}))`. Routes: GET /authorize, POST /token, GET /jwks.
- `assets.rs`: `#[derive(rust_embed::Embed)] #[folder = "../../themes/default/static/"] struct Assets;` handler for
  `GET /assets/{*path}`: lookup via `Assets::get`, content type from `file.metadata.mimetype()`, ETag =
  `aws_lc_rs::digest::digest(&SHA256, &file.data)` hex-encoded (write a tiny hex fn; no new crate), 304 on matching
  If-None-Match, `Cache-Control: public, max-age=3600`. rust-embed rejects paths outside the folder; still assert it in tests.
- `lib.rs`: `WebConfig`, `router()` assembling the above plus `GET /healthz`; `tower`-free besides axum.
- `tests/router.rs`: in-process tests with `tower::ServiceExt::oneshot` and `http_body_util::BodyExt` covering every
