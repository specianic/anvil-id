### End-user flows
- **One mechanism for flow context.** The authorization request (and `ui_locales`) travels with the
  flow, and every link/redirect in the end-user UI is built from it by one function (replacing the
  ad-hoc `links_for` / hardcoded `/ui/login` links). Recovery, verification, email code, second
  factor, MFA enrolment, upstream link confirmation and registration all return to the app.
- **No dead ends:** the "Signed in" page, signed-out page, every error page (incl. `flow_expired`,
  CSRF, missing request) and the tenant root offer a way forward. Prefer the client's
  `initiate_login_uri`/`client_uri` when known, else the sign-in or account page.
- **`return_to` widening is a security change:** extend the exact allowlist to the account pages only,
  with negative tests (open redirect, other tenants, absolute URLs, encoded tricks).
- **PRG** after failed form posts; stale/finished requests are detected on GET (before credentials);
  recovery codes shown on a flow-bound `no-store` GET page that survives reload until confirmed.
- **Error pages:** friendly localized copy (en + de catalogs; honour Accept-Language/ui_locales),
  technical detail only in dev mode.
- **Account area:** header with identity, sign-out and back-to-app; destructive actions confirmed
  (works without JavaScript: confirmation step, not only a JS dialog); otpauth:// link next to the QR;
  readable sessions (device summary, local time where JS is available).
- **Consent** shows the signed-in account and "use another account". Agents never skip consent
  (unchanged).
- No-JS project must keep passing for every changed end-user page.

### Console
- **User management** from the console through the existing admin API: create, invite, edit, block,
  reset password / MFA, delete, search; add a second system admin. Missing API pieces are added with
  security tests and OpenAPI drift updates.
- **Sign-up mode** editable in tenant login settings (not only at tenant creation); rename/label the
  DCR "Client registration" page so it can't be confused with user sign-up.
- **Guided start:** setup success page links to the console; first console visit shows a getting-started
  checklist (create app, sign-up mode, branding, connections).
- **App creation by type** (web, SPA, native, M2M, agent) with correct defaults: SPA and native are
  public clients with PKCE and no secret; M2M hides redirect/consent/PKCE; advanced fields (PAR,
  headless, resources) collapsed. First-party static clients default to the consent mode the guides
  use (`skip_first_party`); agents still always ask. Issuer and discovery URL shown on the created
  page and the app page with copy buttons. Redirect URI validation names the real problem.
- **Upstream connections** are created disabled until required fields are present and the issuer is
  checked; the redirect URI is shown before saving.
- **Safety:** unsaved-changes guard; one Save per form; destructive actions in a confirmed danger zone;
  the built-in `anvil-console` client cannot be deleted (server-side refusal + test).
- **Readable admin identity** (console requests the claims it needs to show email/name).
- Grouped navigation; slug auto-fill from name; readable audit actor/target and grouped action filter;
  CSV import accepted (planner decides client-side conversion vs. server format, one import pipeline
  either way); dry-run report wording fixed; SMTP page states the real fallback.
- **Logo discoverability:** the logo upload is reachable from Branding and the getting-started list.

### Design system (Specianic)
- Apply the Specianic tokens (colour light/dark, type scale, spacing, radius) to the console and to
  the **default** end-user theme. Customer branding (tokens, custom CSS, logo) still overrides the
  default theme; the existing contrast checks stay.
- Fonts Hanken Grotesk and IBM Plex Mono are **self-hosted and embedded** (OFL license files shipped;
  no font CDN, no third-party requests).
- **Do not ship the Specianic wordmark** (the design system marks it a concept pending type design
  and trademark check). AnvilID pages show the tenant's name/logo; the console may use a neutral
  AnvilID text mark.
- Rules to honour: orange (`signal`) is a fill only with ink text on it; `signal-text` for links/focus;
  `danger` distinct from orange and always with icon + label; square corners except interactive
  controls (2px); lines not shadows; sentence case; outline icons (Lucide already in use).
- Copy follows the system's voice: calm, specific, verbs on buttons, no hype.

### Declarative config
- Tenant YAML export/plan/apply carries logos (tenant/client/organization scope) and organizations
  (and what they own, minus runtime data and secrets). Follow docs/COMPATIBILITY.md for the document
  version (additive vs. new version) and keep the JSON Schema and docs/CONFIG-YAML.md in sync.

## Decisions after research (orchestrator defaults, 2026-11-28 — owner may override)
1. **Back to the app:** add optional `client_uri` and `initiate_login_uri` to clients (OIDC registration
   metadata; admin API, YAML, DCR/CIMD where applicable) with a new migration on both backends and an
   rc.3 → rc.4 upgrade test. Fallback when absent: the sign-in or account page.
2. **Org-required non-member (U-M14):** explicit explanation page with "Return to app", which still
   returns `access_denied` to the client.
3. **Logout without a session (U-M4):** the planner checks the conformance logout plans before changing
   behaviour; conformance stays green.
4. **Fonts:** use the official, unmodified upstream releases (Hanken Grotesk from the google/fonts
   repository, IBM Plex from IBM's plex releases), with their OFL license files and pinned sha256 in
   the repo; do not use the design-system subset copies in assets/fonts (provenance unknown; Plex's
   Reserved Font Name applies to modified versions).
5. **Connections:** created disabled; enabling is refused server-side until required fields are
   present and the issuer/discovery check succeeds (no separate test endpoint required).
