# Phase 07.1 Plan 21: Safe and readable account screens Summary

**Destructive account actions now go through a server-rendered confirmation step that needs no JavaScript and is bound to the same flow and CSRF token. Refused profile, email, password and attributes forms follow Post/Redirect/Get with the sealed flash. Account TOTP enrolment offers the otpauth:// link. Sessions show "Firefox on Linux" instead of raw user agents. The Low items L5, L7 and L8 are fixed.**

## Accomplishments

- **Confirmations (U-M12):** one helper (`ui/account_confirm.rs`) and one template (`account_confirm.html`) cover all six destructive actions: remove passkey, remove TOTP, new recovery codes, remove app access, disconnect a linked account and sign out other devices. A POST without `confirm=yes` changes nothing. A confirmed POST without a valid binding gets 403 and changes nothing.
- **PRG for account forms (U-M1):** refused profile, email, password and attributes POSTs answer 303 with the flash. The GET shows the message with the original status (400/503) and the typed profile and attribute values, never the password. The flash is read once. Typed attribute values are dropped from the flash if the cookie would get too large.
- **otpauth link (U-M13, account):** `#link-otpauth` appears only on the no-store enrolment page. It is auto-escaped and shown again after a wrong code.
- **Readable devices (U-M16):** `ui::format::device` uses an allowlist and adds no dependency. Unknown agents show "Unknown browser", and sessions with no agent show "Unknown device". The raw user agent is never rendered.
- **Low items:** the language field is a `<select>` of the supported locales (L5). The empty attributes page no longer repeats the H1 as an H2 (L5). "Last used" is set when a link is created by a sign-in (L7). "Sign out this device" ends on the signed-out page (L8).
- **07.1-09 follow-up:** `available_connections` uses `Connection::is_offerable()`, so incomplete connections are never offered. A test covers it.
