# Phase 07.1 Plan 17: Guided start and settings safety Summary

The console now opens on a tenant Overview. It shows the issuer and discovery URL with Copy buttons and a getting-started checklist computed from real API state. Login settings starts with an editable Sign-up mode, saves with one button and guards unsaved edits. Tenant deletion moved into a typed-slug Danger zone. New tenants get a "Tenant created" page with their URLs. The SMTP page states the real SMTP state, and the logo is the first Branding section, linked from the checklist.

## What was built

**Task 1 (d34b0e6): Overview and landing**
- `routes/index.tsx` redirects `/console/` to `/t/$tenant` (last used tenant or `default`). `routes/t/$tenant/index.tsx` renders the Overview instead of redirecting to Users: the tenant name, a "Connect an app" card (Issuer and Discovery URL CopyFields) and `GettingStarted`.
- `GettingStarted` items (`checklist-{id}`, with `data-state`):
  - first-app: done when static clients other than `anvil-console` in system exist;
  - sign-up: current mode (state info);
  - logo: done when `logo_url` is set; links to `branding#logo`;
  - smtp: done for tenant or installation SMTP, otherwise says no server is configured;
  - connection: done when an enabled connection exists;
  - second-admin (system tenant only): done when `administrator` has 2 or more holders; links to the role page.
- A pending query shows "Checking" and a failed query shows "Could not be checked".
- `lib/smtp.ts`: `fetchTenantSmtp`, `smtpQueryKey`, `useSystemInfo` (same key as the footer) and `smtpState`.

**Task 2 (47111e6): settings, tenant created, SMTP, branding, guards**
- Login settings:
  - The Sign-up section (`#sign-up`) comes first, with Open / Invite only / Disabled radios and explanations.
  - Every section is in one form with a sticky save bar (`save-login-settings`, status "Login settings saved.") and `useFormState` + `useUnsavedChanges`.
  - The "Account creation through connections" option now follows the edited sign-up value.
  - Tenant deletion is a DangerZone (`confirmText = slug`); `default` and `system` keep the `tenant-undeletable` note.
- DCR page: the title is "Dynamic client registration", with an explainer (`registration-explainer`) linking to Sign-up. The inner card heading became "Registration endpoint (RFC 7591)" so the page doesn't show two identical headings. The More settings link was renamed too.
- New tenant:
  - Display name comes first, and the slug follows it through `useSlugFromName`.
  - The "Registration" select is now labelled "Sign-up".
  - On success the page shows "Tenant created" with the Issuer and Discovery URL CopyFields, "Create your first app" (`/t/{slug}/clients/new`) and "Open the tenant overview", and the console remembers the new tenant.
  - Slugs in the tenant list open the Overview.
- SMTP page: `smtp-source` (`data-state` tenant / installation / none / unknown):
  - none is a destructive alert: "No SMTP server configured — verification, recovery and invitation emails can't be sent".
  - The remove button and its dialog wording follow `smtp_configured`.
- Branding: Logo is the first editor section (`id="logo"`). The page scrolls to it once the branding has loaded when the URL hash is `#logo`. ThemeEditor guards unpublished edits (tenant, client and org branding).
- Email templates: guard while subject or bodies differ from the stored template; after a save the form shows the stored values.

**Task 3 (c10490e): e2e**
- `lib/console.ts`: `consoleLogin` has the same signature; `expectConsoleHome` now checks `/console/t/{tenant}`, `tenant-overview` and the "Getting started" heading.
- New specs: `console-first-run`, `console-signup-mode` and `console-safety` (contents as in the plan). The sign-up spec uses `/ui/registration`: that is the real path. The plan says `/ui/register`.
- Updated specs:
  - `console-tenants`: slug fill, created page, Danger zone delete with wrong-case refusal.
  - `console-registration`: new title, plus the orchestrator's 'Dynamic registration' badge text.
  - `console-roles`: the single Save.
