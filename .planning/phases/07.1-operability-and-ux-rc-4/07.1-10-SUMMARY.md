# Phase 07.1 Plan 10: Console form safety for organizations, roles, attributes and webhooks Summary

The console's organization, SAML connection, role, attribute and webhook forms now ask before you leave with unsaved changes. Organization and SAML slugs fill in from the display name. An organization is deleted from a danger zone where you type its slug. Org connections start disabled. `/attributes/new` opens the create form. The console also loads the end-user theme's self-hosted fonts through Vite.

## What was built

**Task 1 (953dabc): slug fill, org danger zone, disabled org connections, attributes/new**
- `OrgForm` and `SamlConnectionForm` use `useSlugFromName`. The slug follows the display name until the admin edits it. An existing slug counts as edited, and the SAML slug only follows in create mode.
- On the organization overview, deletion is now a `DangerZone` at the bottom (`confirmText = org.slug`, action "Delete organization"). It replaces the old ConfirmDialog card.
- Org connections panel:
  - The OIDC create form gets `enabled: false`, and `newSamlValues()` defaults `enabled` to false.
  - A note says new connections start disabled and that the server explains what is missing.
  - The create status message says "(disabled)".
  - Server refusals when enabling show up in the forms: inline for known fields (the SAML `enabled` checkbox shows `errors.enabled`), otherwise in a ProblemAlert.
  - The SAML Enabled hint now explains the enable rule.
- `attributes/new.tsx` is a create page built on `AttributeForm` that navigates to the new attribute after it saves. The list's "New attribute" is now a link to it, and the in-page create card is gone. `routeTree.gen.ts` was regenerated. TanStack's static route outranks `$attributeName`, so `$attributeName.tsx` needed no change.
- `lib/formState.ts` (`useFormState`) holds the values plus a saved baseline and exposes `isDirty` and `markSubmitted`.

**Task 2 (f4211c5): console fonts**
- `src/fonts.css` has @font-face rules for Hanken Grotesk (variable, 100 900, truetype) and IBM Plex Mono 400/500 (woff2), all with `font-display: swap` and relative URLs into `../../themes/default/static/fonts/`.
- `styles.css` imports it on line 2. `vite.config.ts` adds the fonts dir to `server.fs.allow`.
- After the build, `dist/assets` has `HankenGrotesk-wght-<hash>.ttf` and `IBMPlexMono-{Regular,Medium}-<hash>.woff2`. They are byte-identical to the pinned files (`cmp`), and the CSS references them as `/console/assets/...`. `scripts/check-fonts.sh` reports ok, and `dist/` has no googleapis or gstatic references. The fonts were not copied into admin-ui, and neither CSP nor compress.mjs changed.

**Task 3 (6e8c29f): unsaved-changes guards and e2e**
- `RoleForm`, `AttributeForm` and `WebhookForm` (and, from Task 1, `OrgForm` and `SamlConnectionForm`) call `useUnsavedChanges(form.isDirty && !pending)` and render `UnsavedChangesGuard` outside the `<form>`. Each of these forms has exactly one submit button. The separate Cancel button that sat next to the in-page attribute create form went away with that form.
- New spec `console-forms-safety.spec.ts`:
  - org slug fill, including accent folding and how editing the slug stops the fill;
  - a create that navigates without a prompt;
  - the org settings guard (Stay keeps the input; after a save, navigation is free);
  - typed-slug org delete: the button stays disabled for a wrong value or wrong case, Cancel keeps the org, and the org is gone afterwards;
  - `/attributes/new` from the list and opened directly, with the attribute guard and Leave;
  - the role guard with Stay, and how undoing the edit clears it;
  - the webhook in-app guard, then the `beforeunload` prompt via `page.close({ runBeforeUnload: true })`, dismissed so the page stays.
- `console-orgs.spec.ts` covers the danger-zone delete flow and the default-disabled org connection.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Shared dirty-state helper (new file outside files_modified)**
- **Found during:** Task 1
- **Issue:** Five forms needed the same rules: a baseline, reset after a save, and no prompt while the save navigates. Writing that inline five times would break "one implementation per concern".
- **Fix:** Added `admin-ui/src/lib/formState.ts`. It is a new file, so no other plan's file was touched.
- **Commit:** 953dabc

**2. [Rule 1 - Bug] Guard modal inside the form would submit it**
- **Found during:** Task 1
- **Issue:** `Modal` renders in place (no portal), and the console Buttons default to `type=submit`. A guard inside the `<form>` would submit the form when Stay or Leave is clicked.
- **Fix:** Every form renders `UnsavedChangesGuard` as a sibling before the `<form>`, wrapped in a fragment.
- **Commit:** 953dabc, 6e8c29f

**3. [Rule 3 - Blocking] console-org-sso.spec.ts relied on SAML connections being created enabled**
- **Found during:** Task 3
- **Issue:** Domain routing needs an enabled connection (org_domain.rs), and the spec routes a domain to the SAML connection it creates in the UI. With the new disabled default, that step would fail. No wave-2 plan owns this spec, and it is in this plan's wave-end verification list.
- **Fix:** The spec checks that Enabled starts unchecked, then turns it on before saving. The connection is complete, so the server allows it.
- **Commit:** 6e8c29f

### Notes
- The task split is not exact. The OrgForm unsaved guard landed in the Task 1 commit (same file as the slug fill), and so did the SamlConnectionForm guard.
- `organizations/new.tsx` and `attributes/$attributeName.tsx` are in files_modified but needed no change: slug fill lives in OrgForm, and the static `attributes/new` route takes precedence.
- The new guards use `enableBeforeUnload`. An existing e2e spec that leaves one of these forms dirty and then calls `page.goto` could now hit a beforeunload prompt; Playwright auto-dismisses it, which can cancel the navigation. I found none in a quick review. Watch for this in the wave-end run.
- Enabling an org OIDC connection reuses 07.1-09's `ConnectionForm` error display; this plan does not change it.
