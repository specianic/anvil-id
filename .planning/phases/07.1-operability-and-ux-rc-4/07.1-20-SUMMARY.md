# Phase 07.1 Plan 20: Logout ways forward Summary

**Logout never strands the user: no "Sign out?" prompt without a session, "Stay signed in" goes back to a static client's own home, and the signed-out and error pages offer Back to <app> / Sign in again. The conformance contract is unchanged.**

- **Completed:** 2026-11-28
- **Tasks:** 2
- **Files modified:** 11

## Decision 3: conformance logout plans and the no-session behaviour

Read before changing anything: tests/conformance/config.template.json (default `/logout*` block at :62-90, overrides :241-800) and tests/conformance/README.md:200-230.

Browser steps each plan expects. Every plan first signs in through `/authorize*`, so **the browser always has a session when it reaches the end-session endpoint**:

| Plan(s) | Expected browser steps | Path through AnvilID (session present) |
|---|---|---|
| default block (`oidcc-rp-initiated-logout`, `-logout-...` with a registered URI; back-channel plan) | optional "Confirm sign-out" on `/ui/logout*` (click `#logout-confirm-submit`), then land on `*/test/*/post_logout_redirect*` | valid hint gives LogoutNow and a 303 with `state`. Without a hint: Confirm, then POST, then 303 to the URI. Unchanged |
| `-bad-post-logout-redirect-uri`, `-query-added-to-post-logout-redirect-uri` | wait for "The sign-out request is invalid: the post_logout_redirect_uri is not registered for this client." | decision Error (400 page). Unchanged; the page now also has way-forward links |
| `-modified-id-token-hint`, `-bad-id-token-hint` | wait for "...the id_token_hint could not be verified." | Error. Unchanged |
| `-no-id-token-hint` | wait for "...post_logout_redirect_uri requires id_token_hint or client_id." | Error. Unchanged |
| `-no-params`, `-no-post-logout-redirect-uri`, `-only-state` | optional confirm on `/ui/logout*`, then wait for "You have been signed out." | Confirm, then POST, then 303 to `/ui/signed-out`. Unchanged (no `client_id`, so the URL is identical) |

**Choice:** the no-session shortcut applies only to a decision of *Confirm* while the browser has no active session of this tenant. Errors are still decided first and stay errors. A valid hint without a session was already LogoutNow. The conformance plans always carry a session, so none of them takes the new branch. If one ever did, it would still pass: a registered URI goes straight to the `post_logout_redirect` page, and the `/logout*` match skips the optional confirm task. Without a URI, the signed-out page renders at `/logout`, which is outside `/ui/logout*`, so the optional confirm task does not match and the sentence wait succeeds. The contract sentences (logout.ftl, including :22-23) are byte-identical. The only new key is `logout-sign_in_again`. The URL shapes have not changed either: confirmation under `/ui/logout`, signed-out page at `/logout` or `/ui/signed-out[?client_id=]`. **The conformance logout and back-channel plans were not run** (Docker run plus a release build of the shared tree during a parallel wave). They are left for the 07.1-19 gate.

## Accomplishments

- Core `LogoutService`: a module doc section on "Without a session" and an `active_in` helper (one place for "active session of this tenant"). `end_session` returns `LoggedOut { revoked: false }` instead of `Confirm` when there is no session. `start_confirmation` takes the current session and returns `NotSignedIn { redirect, client_id }` with no flow created. The outcomes carry `client_id`.
- `ui/logout.rs`: the `ACCOUNT` constant is gone. `logout_nav` uses `NavContext::for_client`. The cancel link uses `app_home()` or else `NavContext::url(UiPage::Account(Sessions))`. `logged_out_page` fills `page.links` from `error_way_forward`. `/ui/signed-out` reads a single `client_id`. `GET /ui/logout` loads the session.
- `protocol/logout.rs`: passes `client_id` and `signed_in` to the shared helpers.
- `logged_out.html`: way-forward nav (`link-back-to-app`, `link-login` "Sign in again" or "Go to sign in" on errors, `link-account`, `link-console`, `form-sign-out`). `logout_confirm.html` documents the new cancel target.
