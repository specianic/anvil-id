# Phase 7.1 Plan 04: rc.4 storage foundation Summary

**Client home URLs (`client_uri`, `initiate_login_uri`) with additive migrations on both backends and rc.3 -> rc.4 upgrade proofs, a read-only `peek_self_service_token` port for stale-link detection, and `profile email` on the console client.**

## Performance

- **Duration:** about 25 min
- **Completed:** 2026-11-28
- **Tasks:** 3
- **Files modified:** 44 (task 1), 7 (task 2), 2 (task 3)

## Accomplishments

- `Client`, `NewClient` and `ClientUpdate` carry the two optional fields. Both `ClientRepo` backends read and write them in every client query: create, get, list, update, `upsert_cimd`, `get_by_registration_token`. In `ClientUpdate`, `Some(None)` clears a field.
- SQLite `0011_release_1_0_rc4.sql` and Postgres `0009_release_1_0_rc4.sql` only add two nullable TEXT columns. `scripts/check-migrations.sh` passes and the new files are not pinned (07.1-19 pins them at release).
- rc.3 -> rc.4 upgrade tests on both backends. The rc.3 fixture has one static confidential client, one public SPA client, one DCR client and one CIMD client. The tests check that every rc.3 column value and row count is unchanged, the new columns are NULL, `get_by_registration_token` still works, the upgraded rows accept the new fields, and restarting is idempotent. The full contract suite also runs on the upgraded database.
- `UserRepo::peek_self_service_token(tenant, kind, hash, now) -> bool` runs a single SELECT on both backends. Contract tests show it is true only for usable tokens. It is false after verification or recovery consumed the token, after expiry (including `expires_at == now`), and for another kind, another tenant or an unknown hash. Peeking twice leaves the token pending, and the completion afterwards succeeds exactly once.
- The console client now has the scopes `openid profile email admin:read admin:write`. The existing startup drift check updates rc.3 installs, writing one `client_updated` audit event with fields `["scopes"]`; a second start changes nothing. An end-to-end test signs in to the console as a system administrator and gets `email` back from UserInfo.

## Issues Encountered

- The first full Postgres run of `--test upgrade` failed 121 of the new `upgraded_rc3_contract` tests with Postgres error 53100 ("could not resize shared memory segment: No space left on device"). This was the test container's 64 MB `/dev/shm` running out: the run used 12 test threads while other executors also had Postgres containers running. Running the module again with `--test-threads=8` gave 256/256 passed. Every other test in the upgrade binary, including both rc.3 upgrade tests, and the whole `--test contract` binary (256/256) passed in the first run. CI might hit this too if it runs many test threads.
- Following the plan, `just clean-test-containers` ran at the end. It removes every testcontainers-labelled container, so it may also have removed a Postgres test container that a parallel executor was using.
