# Phase 07.1 Plan 08: No dead ends on error, root and setup pages Summary

**Every end-user error page is now localized from the request, explains itself in plain words around the unchanged contract sentence, hides technical detail outside dev mode and always offers a way forward, preferring a static app's own stored home ("Back to <app>"). Every tenant has a root page, and the setup flow leads to the admin console.**

## Performance

- **Duration:** about 50 min
- **Started:** 2026-11-28T03:56Z
- **Tasks:** 3
- **Files modified:** 37 (8 created)

## Accomplishments

- **One error renderer.** The new `errors::error_page_nav` takes the negotiated locale, an `ErrorPage { status, error_key, detail }`, a `NavContext` and `signed_in`. The default-locale `error_page`/`core_error_page` are gone. Every former caller now negotiates the locale: the router fallback (`RequestLocale` plus session lookup), the tenant resolver (`locale_of` on the request headers and query), the theme routes, the CSRF and rate-limit layers, `/authorize` (raw `ui_locales` first, then Accept-Language), `/authorize/continue` and the DCR 404. The logout, invitation, consent and select-* pages already passed a negotiated locale and pick up the new page unchanged.
- **error.html.** Each page shows a friendly heading and explanation per key (`errors_friendly.ftl`, en/de). The contract sentence in `#error-message` is byte-identical (snapshot and HTTP tests compare it with main.ftl). Danger is an inline SVG outline icon with presentation attributes only, plus a text label. `#error-detail` appears only when `page.dev_mode`, otherwise the detail is logged at debug. The status line is kept, and every key gets a `<nav>` way forward (`#link-back-to-app`, `#link-continue`, `#link-login`, `#link-account`, `#link-console`, `#link-home`, `#form-sign-out`). The page still takes a `heading` override, so `login.rs`'s stale-request page keeps working.
- **App home rule (decision 1).** `ui::nav::app_home` returns `initiate_login_uri`, else `client_uri`, and only for `ClientSource::Static` with an absolute http(s) URL. `LiveRequest` carries it. `NavContext::for_client` (for 07.1-20 logout and the 07.1-12 account header) resolves a validated client. `/authorize` errors use the stored client named by `client_id`. `/authorize/continue` errors use the request's client, looked up before resuming, so the page never links back into the same continuation.
- **Root pages.** `/` and `/ui` on every tenant: signed out shows sign-in; signed in shows the account link and the sign-out form (plus the console in the system tenant); the default tenant adds a discreet `#link-administration` to `/console/`. Before setup they show "Setup is not complete" with `anvilid admin setup-url`. The responses are `no-store`.
- **Console before setup.** The `/console/` index routes serve the same server-rendered guidance with the console CSP until an administrator exists. Assets are unaffected. `console::routes` now carries `AppState`.
- **Setup.** On the success page the primary action is `#link-console`, and the credentials sit under "For automation" (`#setup-automation`). Reopening a setup link after setup answers 200 "Setup is already complete" with `#link-console` instead of 403.
- **e2e.** New `error-pages.spec.ts`. `a11y.spec.ts` now covers pre-setup `/` and `/console/` guidance, the setup page console link, the not-found page, the reopened setup link and a root-page audit. `i18n.spec.ts` gains German and English error pages with the contract sentences checked.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `BootstrapService::setup_complete` added in anvil-core**
- **Found during:** Task 2
- **Issue:** The plan asks for the setup state "through core, not storage directly", but no core read for "installation has an administrator" existed. `crates/anvil-core/src/service/bootstrap.rs` is not in this plan's files_modified, and no wave-2 plan lists it.
- **Fix:** A small additive read-only method (system tenant exists and its user list is non-empty).
- **Commit:** 6bc7bce

**2. flow_expired "Back to <app>" behaviour test**
- **Issue:** A `flow_expired` page cannot name a client. The request is expired or deleted by then, so `get_authorization_request` no longer returns it.
- **Fix:** The app-home preference on error pages is covered by a nav unit test (live request with a static app home, then error way forward, with the app first) and by HTTP tests on `/authorize` `redirect_uri_mismatch` and on an `/authorize/continue` error after the client changed (`continuation_error_goes_back_to_the_static_app`).

**3. Used setup link vs. forged token**
- **Issue:** Once setup is complete, consumed and forged tokens cannot be told apart without a new storage port.
- **Fix:** Both get the "already complete" page on GET, which grants nothing. POST and pre-setup GET keep the 403 refusal. Covered by tests (see decisions).

## Deferred Issues

- **C-L6 (Low, deferred in writing per plan):** server stdout mixes pretty log lines with JSON audit events, so the "Setup URL" line is easy to miss. The log and audit format is an operator contract covered by the telemetry redaction tests (05-26). Mitigation here: the root page and `/console/` before setup name `anvilid admin setup-url`.
- `ui/login.rs` (07.1-07) calls `too_many_requests(...)`, which renders the 429 page in the tenant default language; it should call `too_many_requests_in(..., &loc, ...)`.
- `AppState::authorize_response` (used by consent, select-account and select-organization) renders an `ErrorPage` outcome in the tenant default language, because those callers pass no locale. Their owners can switch to a localized variant.
- `ui/logout.rs` `ACCOUNT` still builds `/ui/account/sessions` by hand. It was left for 07.1-20 (logout behaviour), since this plan's logout edits were limited to error pages, and those already used the negotiated locale (no change was needed in `ui/logout.rs`, `protocol/logout.rs` or `ui/invitation.rs`).
- `/authorize` with a pushed request (`request_uri`) reads `ui_locales` from the query only, not from the pushed parameters.
- `flow_nav.rs` has 5 failures from 07.1-07's in-progress PRG change (POST now answers 303). They are outside this plan.
- 07.1-19 should add `#link-back-to-app`, `#link-home`, `#link-administration`, `#error-label`, `#error-explanation`, `#setup-command`, `#setup-automation` to the selector contract.
