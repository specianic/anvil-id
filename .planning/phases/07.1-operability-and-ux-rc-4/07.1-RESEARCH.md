## Summary

The end-user dead ends have one root cause: the authorization request id lives on the flow row
(`Flow.auth_request_id`, model/flow.rs:36-47) but the web layer rebuilds page links from the **query
string** only at flow start (`links_for(..., request)`, login.rs:1178), and every re-render after a POST
passes `None` (`outcome_response_with`, login.rs:1797/1813/1821; `drive_response` CAPTCHA path :1714;
`restart_login` :1636). The recovery link never carries the request (login.rs:1196), message pages always
link plain `/ui/login` (login.rs:1509), email_code.rs:308 hardcodes it, mfa.rs:99-102 bounces GET to bare
`/ui/login`, and emailed recovery/verification links contain only the token (service/flow.rs:3596). The
fix is one web-side `NavContext` resolved from the flow row (the driver already has `flow_meta`,
flow_driver.rs:1005-1023) plus carrying `request=` on emailed links built in core. **No migration is
needed**: tokens stay as they are; the request id rides on the emailed URL and is validated on GET.

Error pages ignore the browser language because `errors::error_page` (errors.rs:114-124) uses the tenant
default locale and is the variant used by the router fallback, tenant resolution, `/authorize`, the CSRF
layer, the rate limiter and theme routes. Conformance automation matches some English error sentences
verbatim (tests/conformance/config.template.json:208,232,297,362), so friendly copy must be **added
around** those sentences, never replace them.

Console user management is almost entirely a UI job: the API already has create (password or invite),
patch (email, verified, status, username, claims), delete, credential removal, session revoke, exact email
search, tenant PATCH of `registration`. Server work is small and all touches the OpenAPI document (one plan
should own `admin-v1.json`, `schema.d.ts` and the `openapi_drift.rs:90` operation count of 130). The
Specianic switch touches three mirrors of the default palette (anvil.css, `LIGHT/DARK_DEFAULTS` in
policy/branding.rs:204-239 kept in sync by a test, ThemeEditor.tsx:46-76 not synced), needs a new
`--anvil-link` variable (links currently use `--anvil-primary`, anvil.css:184-185, which would put orange
text at 3.0:1), and needs `font-src 'self'` in every end-user CSP (the strict CSP is `default-src 'none'`
with no font-src, security_headers.rs:12-13). Organizations in YAML **reverse a documented 1.0 decision**
(CONFIG-YAML.md:38-56; security-map rows 1042-1045), so the four mapped tests must be rewritten, and
"absent `organizations` key" must keep meaning "do not touch organizations" or `--prune` becomes
destructive for existing documents.

**Primary recommendation:** Wave 1 builds the shared foundations in disjoint files (NavContext + emailed
request; end-user tokens/fonts/CSP; console tokens/shell/shared components; all admin-API additions with
the single OpenAPI regen; e2e helper port), then screen plans fan out in waves 2-3, with one gate plan
owning the security map, theme README, version bump and the owner tag checkpoint.

## Architecture Patterns

### 1. End-user flow context (U-H1, H2, H6, H7, M1, M10, M11)

#### 1.1 Current state (cited)
- Request id enters via `UiQuery.request` (login.rs:973-983), parsed by `auth_request()` (:1009-1016);
  the flow is created with it (`FlowService::start`, service/flow.rs:814-823 → `create_flow(..., auth_request)`),
  so `Flow.auth_request_id` is authoritative after start.
- `ui_locales` travels separately as `&ui_locales=` on URLs (`carry_ui_locales`, i18n.rs:551) and via the
  stored request's params (`page_locale`, login.rs:301-327; `locale_for_request`, i18n.rs:482).
- `return_to` (invitation only) is sealed into `LoginState.return_to_sealed` (flow.rs:355-396);
  `continuation_of` gives `Continue::Authorize(request)` first, else `Continue::Return(target)`.
- Lost-context points: login.rs:1196 (recovery link never has request), :1509 (message page link),
  :1636 (`restart_login` passes `None` and starts a request-less login), :1714/:1797/:1813/:1821
  (re-renders pass `None`), email_code.rs:308, mfa.rs:99-102, account `to_login` redirects
  (account_security.rs:133, account_profile.rs:122, account_sessions.rs:104, account_linked.rs:111,
  account_apps.rs:90, account_attributes.rs:425), flow.rs:3596 emailed link.
- Templates do **not** hardcode `/ui/login` (the review's suspicion): they all render
  `page.links.login|registration|recovery` (second_factor.html:85-87, mfa_enroll.html:87-89,
  email_code.html:41-43, upstream_link.html:77-79, registration.html:6-8, recovery.html:7-9,
  magic_link.html:15-17). Fixing the link builder fixes them.

#### 1.2 Recommended design: one `NavContext` (new file `crates/anvil-web/src/ui/nav.rs`)
```rust
// Sketch — the single place that turns flow context into URLs (replaces links_for and every
// hand-built "/ui/login" in ui/*). Resolved once per response.
pub(crate) struct NavContext {
    request: Option<AuthRequestId>,      // only if the request exists, belongs to this tenant, unexpired
    client_name: Option<String>,         // for "Continue to <app>" copy
    return_to: Option<ReturnTarget>,     // allowlisted target (invitation / account pages)
}
impl NavContext {
    pub(crate) async fn from_query(state, tenant, q: &UiQuery) -> Result<Self, StaleRequest>; // GET entry
    pub(crate) async fn from_flow(state, tenant, flow: FlowId) -> Self;    // re-renders, PRG GET
    pub(crate) fn none() -> Self;
    pub(crate) fn url(&self, tenant: &ResolvedTenant, loc: &Locale, page: UiPage) -> String;
    pub(crate) fn links(&self, tenant, loc, form_id: &str) -> PageLinks;  // replaces links_for
    pub(crate) fn way_forward(&self, tenant, loc, session: Option<&BrowserSession>) -> WayForward;
}
pub(crate) enum UiPage { Login, Registration, Recovery, Verification, Account(AccountSection), SignOut, Console }
```
- `from_flow` uses the existing `flow_driver::flow_meta` read (one SELECT through the `FlowRepo` port —
  no handler touches storage directly, CLAUDE.md rule holds because flow_driver goes through the port).
- `url()` appends `?request=` (and `&ui_locales=` via `carry_ui_locales`) for Login/Registration/Recovery
  so every detour keeps the request. `PageLinks` gains `account`, `sign_out`, `continue_to` (Option) so
  message/error templates can render a way forward.
- `way_forward()` order: live request → `/ui/login?request=` (or `/authorize/continue?request=` when a
  session exists); else signed-in → account page (+ console link in the system tenant, URL
  `{public_url}/console/`); else tenant sign-in. Client `initiate_login_uri`/`client_uri` cannot be used
  today: **the `Client` model has neither field** (model/client.rs:122-170; DCR accepts `client_uri` as
  informational and drops it, oauth/registration.rs:103/553). See Open Question 1.
- Emailed links: change `self_service_email` (service/flow.rs:3558-3606) to take
  `request: Option<AuthRequestId>` and append `&request={id}`; callers pass `exec.flow.auth_request_id`
  (IssueRecovery :2990-3009, CreateUser verification :2900-2912). The admin invite (service/user.rs:102-130)
  and upstream JIT (service/upstream.rs:1570) pass `None`. **Nothing is stored on the token.**
  `recovery.rs`/`verification.rs` `show` start the flow with the validated request
  (`start_page(..., request, token)` already accepts it).
- `message_page` (login.rs:1499-1532) becomes `message_page(state, tenant, loc, key, &nav, jar)`;
  `recovery.done` / `verification.done` / `registration.check_email` render "Continue to <app>" when
  `nav.request` is live.

#### 1.3 PRG (U-M1) — feasibility per form
CSRF tokens are stored only as a hash (`Flow.csrf_hash`), so a GET cannot re-show the posted token
(mfa.rs:97-98 says exactly this). Recommended:
- **Derived CSRF**: at flow creation set `csrf = b64url(hmac_sha256(kek.derive_key("anvilid/ui-csrf/v1"),
  tenant_id || flow_id || cookie_token))` and store `csrf_hash = hash(csrf)` as today. A PRG GET with the
  flow cookie recomputes it and checks the hash — no storage change, binding semantics unchanged (the
  token is only computable with the HttpOnly cookie + KEK). Headless API browser mode is unaffected
  (still posts what it received); native mode uses flow tokens (`FlowBinding::Token`) — keep it.
- **Flash**: failed POST → `303 /ui/<page>?flow={id}` + a one-shot sealed flash cookie
  (`{prefix}anvil_flash_{t}`, SameSite=Strict, HttpOnly, short Max-Age, KEK purpose
  `anvilid/ui-flash/v1`, AAD tenant+flow) carrying only form-level/field-level message keys + args and the
  non-secret field values (identifier, name). Never passwords, codes, CAPTCHA responses. The GET renders
  `flow_driver::current_step` (flow_driver.rs:1028-) + flash messages with status 400 when the flash
  has an error (keeps `form_status` semantics for the page that is shown).
- Per form:
  | Form | PRG | Notes |
  |---|---|---|
  | login / identify / sso-choice | yes | brute-force lock (429 + Retry-After) and CAPTCHA demand stay **direct** responses (no redirect) |
  | registration, recovery request, recovery reset, verification | yes | reset/verification token stays in the hidden field: current_step must re-emit it from flow state |
  | second factor | yes | `factor_token` must survive: put it in the flash (it is a sealed binding token, mfa.rs:61-97) or re-seal from flow state; today GET → /ui/login (mfa.rs:99-102) must become the PRG GET |
  | MFA enrol (TOTP) | yes with care | pending secret is in flow state; QR must be re-derived on GET; `swap_state` single-use semantics unchanged |
  | email code | yes | resend action keeps flow |
  | passkey JSON endpoints | no | JSON, not pages |
  | account forms (settings flows) | yes | separate plan; same helper |
  | consent / select-account / select-org / logout confirm | already GET-rendered pages; their POSTs end in redirects |
- Stale detection on GET (U-H6/M11): `/ui/login?request=X` with an unknown/expired/other-tenant request
  → `flow_expired` page with way forward (no form). `/ui/recovery?token=` and `/ui/verification?token=`:
  check the token is unconsumed/unexpired on GET through a **read-only** port lookup (the token must not
  be consumed by GET — mail scanners, verification.rs:3-4) and show "link expired — send a new one"
  (recovery request form / resend verification) instead of the form.

#### 1.4 Recovery codes (U-H7)
Today the codes are rendered in the POST response (`signed_in_response`, login.rs:1746-1771,
`mfa_enroll.html` with `continue_url`). Recommended: on `FlowOutcome::SignedIn/SteppedUp` with codes,
keep the flow alive (do not `clear_flow`), store the codes **sealed** in the flow state (KEK purpose
`anvilid/flow-recovery-codes/v1`, AAD tenant+flow), 303 to `GET /ui/login/recovery-codes?flow=`
(flow-cookie bound, `Cache-Control: no-store`), which shows them plus "I saved them, continue" (POST,
CSRF) → deletes the sealed codes and the flow, then 303 to `nav.way_forward`. Flow lifetime is 15 min
(`FLOW_LIFETIME`, flow.rs:198). Plaintext scans (`anvil-storage-*/tests/plaintext.rs`) must cover the new
sealed field.

#### 1.5 Account area (U-H3, H4, M12, M13, M16)
- `account_base.html` gets a header block: identity (email, from the session user), "Sign out" (POST form to
  the existing sign-out route — no GET logout), "Back to <app>" only when a target is known (Open Q1).
- No-JS destructive confirmation: first POST (without `confirm=yes`) renders a confirmation page with the
  same settings binding; the second POST with `confirm=yes` performs. Negative test: a POST without

### Anti-Patterns to Avoid
- **Building URLs in handlers or templates** (`tenant.ui_url("/ui/login")` scattered in 10+ places):
  every link goes through `NavContext::url`.
- **Trusting `request=` from a query/link without lookup**: always resolve through the grants port and
  drop silently when unknown/expired/other tenant (theme.rs:86-123 shows the same "silently fall back,
  no oracle" pattern).
- **Redirecting the signed-in page** (H2): 30+ Rust tests and several e2e specs assert the
  `login.signed_in` message page; add links instead.
- **Rewording contract sentences** (error.html:2-3 comment; conformance config).
- **Changing API defaults** (`enabled: true` for connections) instead of console defaults + a
  server-side display rule.
- **Second CSV parser on the server** / second token endpoint style duplication (CLAUDE.md).
- **Committing scratchpad paths or screenshots** with local paths (public repo).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Navigation guard | custom `beforeunload` + router patching | TanStack `useBlocker` (`shouldBlockFn`, `enableBeforeUnload`, `withResolver`) | handles in-app + tab close |
| Icons | hand-drawn SVGs in console | lucide-react | consistent outline set |
| CSRF re-show | storing plaintext CSRF in flow state | KEK-derived HMAC (`Kek::derive_key` + `hmac_sha256`) | no secret at rest, no port change |
| Sealing flash/codes | ad-hoc encryption | `Kek::seal/open` with purpose + AAD tenant/flow (pattern: flow.rs:360-387) | existing reviewed primitive |
| Locale negotiation on error pages | parsing Accept-Language again | `i18n::negotiate` / `RequestLocale` | one negotiation |
| UA parsing for sessions | regex soup | keep the existing `ui/format.rs` helpers, extend with a small browser/OS family mapping; or show "Browser on OS" from a short allowlist | no new dependency needed |
| Organization/connection writes from YAML | direct storage writes | the owning services (audit + validation) | config.rs pattern |
| Contrast math | new code | `contrast_ratio` (policy/branding.rs:194) | existing tests |

**Key insight:** almost everything needed exists (flow row has the request, flow_meta/current_step exist,
API endpoints exist, KEK primitives exist); the work is routing data through one function and
replacing duplicated defaults, not inventing mechanisms.

## Common Pitfalls

### Pitfall 1: Hidden shared files break parallel waves
**What goes wrong:** two plans edit the same file and the second overwrites or conflicts.
**Hidden shared files found:** `crates/anvil-web/src/ui/login.rs` (links, message page, PRG, recovery
codes), `docs/openapi/admin-v1.json` + `admin-ui/src/api/schema.d.ts` + `openapi_drift.rs:90` (admin API
and YAML plans), `scripts/check-security-tests.sh` (one heredoc), `themes/default/README.md` (selector
contract), `crates/anvil-web/tests/snapshots/*.snap`, `admin-ui/package-lock.json`, `AppShell.tsx` +
`lib/tenant.ts`, `themes/default/locales/{en,de}/main.ftl` (avoid: add per-feature `.ftl` files — the
loader takes every file and the parity test is per file; a duplicate message id across files is a startup
error), `protocol/authorize.rs` (error pages AND form_post CSP), `layers/security_headers.rs` (CSP),
`policy/branding.rs`, `mfa_enroll.html` (recovery codes AND otpauth), `docs/ARCHITECTURE.md:1040`
(return_to row), `.planning` docs.
**How to avoid:** assign each to exactly one plan per wave (see §8).

### Pitfall 2: Conformance relies on page sentences and URLs
Sentences: error-redirect_uri_mismatch and logout-* (config.template.json:208,232,297,362; README:200-217).
URLs: confirmation under `/ui/logout`, signed-out page not under `/ui/logout` (ui/logout.rs:9-11).
Changing logout prompts (U-M4) or error copy must keep both; run the conformance workflow before the gate.

### Pitfall 3: Signed-in page and form statuses are widely asserted
`login.signed_in` appears in ~30 Rust test files and several e2e specs; failed forms assert 400
(security_bruteforce.rs has 13 such checks). PRG changes POST answers to 303 — give the Rust test support
(`tests/support`, `tests/ui_helpers`) a `post_form_follow` helper and migrate in the PRG plan; keep 429
lock pages direct.

### Pitfall 4: Orange text
`a { color: var(--anvil-primary) }` (anvil.css:184-185), active nav border (:497) and several `color:
var(--anvil-primary)` rules (:304, :359) would render orange text (3.0:1 on canvas). Every text/icon use
must move to `--anvil-link`/`--anvil-focus`; axe runs in light and dark (a11y.spec.ts) and will catch it.

### Pitfall 5: Fonts blocked by CSP
`default-src 'none'` without `font-src` blocks `@font-face` on every end-user page silently (fallback font
shows; no test fails). Add an e2e assertion `document.fonts.check('16px "Hanken Grotesk"')` after load.

### Pitfall 6: Font licensing provenance (LOW confidence)
The provided woff2 files are 13-15 KB, which suggests subsets. IBM Plex is OFL with Reserved Font Name
"Plex"; under the OFL a subset is a Modified Version and may not keep the reserved name without
permission. Use unmodified files published by the font projects (IBM publishes its own web subsets) and
ship their OFL texts; record the source/version in a `fonts/README` or THIRD-PARTY notice. Owner check.

### Pitfall 7: Organizations in YAML vs. prune
An existing document applied with `--prune` after this change must not delete organizations. Absent key =
unmanaged; never prune orgs in rc.4; domain verification never declarable.

### Pitfall 8: Admin identity needs UserInfo
Adding `email profile` scopes alone does not fix the header: ID tokens carry no scope claims
(claims.rs:4-5). Set `loadUserInfo: true` in oidc-client-ts.

### Pitfall 9: Request TTL vs. email latency
Requests expire after 15 min. A verification link opened tomorrow cannot continue the app; the page must
fall back to sign-in/account gracefully (not an error).

### Pitfall 10: Disk and build cost
`tests/e2e/run.sh` builds the console and a release binary every run; per-task checks should use
targeted `cargo test -p anvil-web --test <file>`; run e2e per wave; clean `target/` and test containers
after waves (owner preference).

```rust
// Source: pattern from crates/anvil-jose/src/email_code.rs:52 (hmac_sha256) and kek.rs:102 (derive_key)
fn flow_csrf(kek: &Kek, tenant: TenantId, flow: FlowId, cookie_token: &str) -> String {
    let key = kek.derive_key("anvilid/ui-csrf/v1");
    let mut msg = Vec::with_capacity(48 + cookie_token.len());
    msg.extend_from_slice(tenant.0.as_bytes());
    msg.extend_from_slice(flow.0.as_bytes());
    msg.extend_from_slice(cookie_token.as_bytes());
    b64url(&hmac_sha256(&*key, &msg))
}
```

## Open Questions

1. **"Back to app" / client home URL**
   - What we know: the `Client` model has no `client_uri` or `initiate_login_uri`
     (model/client.rs:122-170); DCR validates `client_uri` and discards it. Without a stored URL, account
     pages, "Stay signed in" on logout, and expired-request pages cannot link back to an app.
   - What's unclear: whether the owner accepts a schema change in rc.4.
   - Recommendation: add optional `client_uri` and `initiate_login_uri` to static clients (admin API
     optional fields, YAML optional keys, DCR persists `client_uri`), nullable columns in a new migration
     (SQLite 0011, Postgres 0009) with an rc.3→rc.4 upgrade test; validated as absolute https (http
     loopback in dev), never taken from requests. If the owner declines, fall back to sign-in/account
     pages everywhere and drop "back to app" from the account header (CONTEXT allows "else the sign-in or
     account page").
2. **Org-required non-member (U-M14)** — show an explicit "You are not a member of <org>" page with
   sign-out/other account instead of a silent `access_denied`? That changes protocol behaviour (the RP
   currently receives the error). Recommend: show the page with a "Return to app" button that continues
   with `access_denied`, so RPs still get the error.
3. **Logout without session (U-M4)** — redirect to a validated `post_logout_redirect_uri` directly, or
   show the signed-out page? Both are spec-compliant; verify against the conformance logout plans before
   choosing.
4. **Font file provenance** (Pitfall 6) — owner confirms the source of the woff2 files.
5. **Upstream "check issuer" endpoint** — required ("the issuer is checked") or is "created disabled +
   not offered without secret" sufficient for rc.4? Recommend implementing the check endpoint (small,
   additive, SSRF-guarded port already exists).
