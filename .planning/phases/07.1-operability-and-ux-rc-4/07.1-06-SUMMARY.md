# Phase 7.1 Plan 06: rc.4 admin API additions Summary

**Client home URLs settable through the admin API, DCR and CIMD under one validation function, a 409 guard on deleting the built-in console client, redirect URI errors that name a missing scheme, an admin-sent password-reset email through the self-service recovery path, and `smtp_configured` on system info. The OpenAPI document was regenerated once (131 operations).**

## Performance

- **Duration:** about 90 min
- **Completed:** 2026-11-28
- **Tasks:** 3
- **Files modified:** 32

## Accomplishments

- `validate_client_home_uri(field, value, allow_http_loopback)` in `service/client.rs` is the only home URL rule. It requires an absolute https URL with a host, no userinfo, no fragment, no whitespace or control characters, and at most 2048 bytes. http is allowed only for localhost/loopback when the caller permits it. Admin create and update, DCR (`oauth/registration.rs`) and CIMD (`oauth/cimd.rs`) all call it. Refusals are `Validation` on `client_uri` / `initiate_login_uri`: a 422 naming the field in the admin API, `invalid_client_metadata` "client_uri: ..." in DCR, and the existing invalid-document error in CIMD. The value is never echoed.
- Admin API: `client_uri` and `initiate_login_uri` are optional on `CreateClient`, double-option on `UpdateClient` (null clears, absent keeps), and always present (possibly null) on `ClientView`. The DTO descriptions and the `ClientOptions` doc comments state the rule: values are stored and shown to admins, but end users see them only for static clients. This plan adds no rendering.
- DCR now stores `client_uri` instead of dropping it, accepts `initiate_login_uri`, and returns both in the registration and RFC 7592 read responses (`client_metadata`). Neither can be set by DCR or CIMD unless the request or document carries it.
- CIMD: `NewClientMetadata` carries both values from the document and `to_new_client` stores them.
- `ClientService::delete` refuses `anvil-console` in the system tenant with 409 "The console client is built in and cannot be deleted" before any write, so no audit event is recorded. A client named `anvil-console` in any other tenant deletes normally. Declarative config already skipped the console client, so prune is not affected.
- `validate_redirect_uri`: `localhost:5173/cb`, `127.0.0.1:8080/cb` and `app.example/cb` now get "redirect URI is missing its scheme: add http:// (localhost only) or https://". http to a non-loopback host gets "...only allowed for loopback addresses and localhost; use https". DCR returns the same text because it reuses the function. Accept and refuse decisions are unchanged: native custom schemes such as `myapp:1234/cb` are still accepted, and a unit test plus a proptest cover this.
- `UserService::send_recovery` builds the token and email with `flow::self_service_email` (Recovery kind, 1 h, `{issuer}/ui/recovery?token=`, sealed payload) to the user's current address. It stores both through `issue_self_service_token` in one transaction and audits `user_recovery_sent` with the admin actor and no details. The route `POST /tenants/{slug}/users/{user_id}/recovery` (`sendUserRecovery`) needs `admin:users:write` or `admin:write`. It returns 202 with an empty body, 404 for another tenant's user or an unknown id, and 409 for a blocked user.
- `GET /system/info` returns `{ version, smtp_configured }`, where `smtp_configured` comes from `Config.installation_smtp`.
- `docs/openapi/admin-v1.json` and `admin-ui/src/api/schema.d.ts` were regenerated once; `openapi_drift` now expects 131 operations. `check:api` and `typecheck` pass. `ACTION_SET` in the console audit page has the new `user_recovery_sent` key.

**3. [Rule 1 - Bug] The `api_compat` comparator flagged a new operation's required path parameters as breaking**
- **Found during:** Task 3
- **Issue:** `breaking_changes` counted every new `required request` fact, even for an operation the baseline does not have. A new operation is additive per COMPATIBILITY.md.
- **Fix:** New required inputs now count only for operations present in the baseline. A new operation with required path parameters and a required body was added to `api_compat_allows_added_optional_field`. The baselines were not edited, and the detection tests for existing operations still pass.
- **Files modified:** `crates/anvil-web/tests/api_compat.rs`
- **Commit:** 2791fca

- **Fix:** The expected body now includes `"smtp_configured": false`; the test environment is cleared, so no SMTP URL is set.
- **Commit:** 2791fca

**5. [Spec nuance] Home URL http rule on the admin path**
- The plan says "http only for loopback in dev mode". `ClientService` has no dev-mode input, and redirect URIs and back-channel logout URIs on the same path already allow loopback http in every mode. Admin-registered clients therefore follow the same rule. DCR never accepts http, and CIMD accepts it only in development mode.
