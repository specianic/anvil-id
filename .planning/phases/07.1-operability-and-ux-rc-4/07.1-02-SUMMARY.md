# Phase 07.1 Plan 02: Specianic default theme and self-hosted fonts Summary

The default end-user theme now uses the Specianic tokens in light and dark: warm neutrals, orange
buttons with ink text, signal-text links and focus, 2 px controls, square cards, no shadows. It
self-hosts the official, byte-identical Hanken Grotesk and IBM Plex Mono files, whose pinned hashes
are checked in `just ci`. Every end-user CSP adds `font-src 'self'` and nothing else. Customer
branding keeps its look, and stored themes are never newly refused.

## What was built

**Task 1, fonts (18f40cb).** I downloaded `HankenGrotesk[wght].ttf` (132,892 bytes, matching the
listing) and `OFL.txt` from google/fonts at `c1eda9233c33ad7775b27efd794f931095cf6133`. I also
downloaded `ibm-plex-mono.zip` from the `@ibm/plex-mono@2.5.0` release with `gh release download`.
From the zip I copied only the complete (not split) `IBMPlexMono-Regular.woff2` and
`IBMPlexMono-Medium.woff2` and the package `LICENSE.txt`. All downloads went into a fresh scratchpad
directory. `SOURCES.md` records each URL, the commit or tag, the retrieval date, the OFL 1.1 licence,
the Plex Reserved Font Name rule ("unmodified; do not subset") and the statement that the files are
byte-identical. `SHA256SUMS` covers the 3 fonts and both licences. `scripts/check-fonts.sh` runs
`sha256sum -c`, fails on any `.ttf` or `.woff2` that `SHA256SUMS` does not list, and fails when an
OFL text is missing. Its `--self-test` proves that a flipped byte, an unlisted font and a missing
licence are each rejected. The `just fonts-check` recipe runs both modes and is in the `ci`
dependency list.

**Task 2, tokens, defaults, overrides and CSP (b451abb).**
- `anvil.css` contains:
  - the token mapping from the plan;
  - 3 `@font-face` rules: Hanken as a variable face for weights 100-900, Plex at 400 and 500, all with
    `font-display: swap` and relative `fonts/` URLs;
  - the variables `--anvil-link`, `--anvil-success`, `--anvil-card-radius`, `--anvil-font-mono`,
    `--anvil-text-body`, `--anvil-text-small` and `--anvil-space-{1,2,3,4,6,8,12,16}`.
- Every margin, padding and gap that matches a spacing step now uses the token.
- Code and textarea use the mono font.
- `main`, panels, callouts, disclosures, the CIMD box and the QR frame use `--anvil-card-radius`.
- Links, outlined buttons, the disclosure summary and the active-nav bar use `--anvil-link`. The input
  focus border uses `--anvil-focus`. The `main` box-shadow is gone.
- `LIGHT_DEFAULTS`/`DARK_DEFAULTS` now hold 17 entries each, matching anvil.css (adds `--anvil-link` and
  `--anvil-success`). These tables also feed the pinned dark block, so a light-only brand never shows
  the dark link colour.
- `theme_stylesheet` derives `--anvil-link`, `--anvil-focus` and `--anvil-card-radius`. When only one
  side of the button pair is customised, it pairs that colour with the legacy partner. In the dark
  block it looks at the light colours as well, because light values leak into dark.
- New core tests:
  - `stylesheet_derives_link_focus_and_card_radius`
  - `lone_button_colour_keeps_its_legacy_partner`
  - `default_palette_meets_contrast`: ink on orange is over 6:1; text, link and danger reach 4.5:1 on
    bg, surface and code-bg; muted and success reach 4.5:1; focus and input border reach 3:1
  - `anvil_css_keeps_orange_a_fill_and_has_no_shadows`: reads the embedded file
  - proptest `single_colour_themes_valid_before_stay_valid`: any single checked colour that passed
    against the old defaults still passes
- CSP: `font-src 'self'` was added to the layer `CSP` (which also covers `LOGIN_CSP` through
  `ACCOUNT_CSP`), `ACCOUNT_CSP`, `PREVIEW_CSP`, the form_post CSP and the CAPTCHA builder. Only the
  constants changed.
- CSP tests:
  - `csp_is_strict` asserts `font-src 'self'` and no http(s) or `*` source.
  - `security_csp.rs` requires exactly one `font-src 'self'` directive and no external source on every
    UI page.
  - The exact strings in `shell.rs` and `security_theme.rs` are updated.
  - `response_mode.rs`, `account_security.rs` and the CAPTCHA unit test assert `font-src 'self'`.
- README:
  - The ground rule now reads "no external fonts".
  - Custom CSS cannot add `@font-face`; custom web fonts have to ship in a theme directory.
  - It documents the override derivations and the legacy button partner.

## Type scale choice

- Body text is 15/24 px and small text 13/20 px.
- The page `h1` on the narrow sign-in card uses the token **h2** size (24/30 px, weight 500,
  -0.01em). The 40 px h1 token is for wide pages and would wrap badly in a 26rem card.
- Card and section `h2` uses the **h3** token (18/24 px, 600).
- All sizes are in rem, so the user's font-size setting still scales them.
- Inputs keep 16 px text so iOS Safari does not zoom on focus.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Legacy partner for a lone customised button colour**
- **Found during:** Task 2
- **Issue:** The new default `primary_text` is ink (#0f0f10). A stored theme that customised only
  `primary`, for example a dark blue, was validated against white before. Next to ink it would be
  refused below 3:1 and render dark text on its button. A theme that customised only `primary_text`
  (for example light grey) would be checked against orange and refused. Both break the must-have
  "stored themes are never newly refused".
- **Fix:** `button_partner()` pairs the lone colour with the pre-1.0 default for that scheme, in both
  `check_contrast` and `theme_stylesheet`. The dark block restores the dark legacy text when the
  light partner would otherwise leak into it. Tests and a proptest prove that themes valid before
  stay valid. The text, bg and surface pairs need no fallback: the new defaults only increase the
  contrast of any pair that passed before, and the proptest covers this.
- **Files modified:** crates/anvil-core/src/policy/branding.rs, themes/default/README.md
- **Commit:** b451abb

**2. [Rule 1 - Bug] Executable bit on OFL-IBMPlex.txt**
- The IBM zip ships `LICENSE.txt` with mode 755. I changed it to 644 in b451abb. The bytes did not
  change, so the hash is unaffected.

**3. theme.rs CSP left unchanged (plan listed it)**
- The only CSP in `theme.rs` is `default-src 'none'` on the logo and stylesheet responses. Those are
  subresources. Their CSP does not govern font loading, which follows the document's CSP, and they
  never load fonts themselves. Adding `font-src` there would loosen a deny-all for no effect, so
  `tests/theme.rs` (which asserts `default-src 'none'`) needed no change either.

**4. Verify command detail**
- `just --dry-run ci | grep fonts-check` cannot match, because a dry run prints commands
  (`scripts/check-fonts.sh`), not recipe names. I verified with `just --show ci | grep fonts-check`
  and confirmed that the dry run lists both check-fonts commands.
