# Phase 07.1 Plan 16: Guided app creation, Integration card, safe client actions Summary

Creating a client now starts with "What are you building?". Each of the five app types fills in working defaults: SPA and native apps are public with PKCE, web apps are confidential, machine-to-machine clients have no sign-in fields, and agents always ask for consent. Every client shows an Integration card with the issuer, discovery URL, client ID and redirect URIs, each with a Copy button, plus a `.env` snippet. The secret appears on the card only on the created page. Deleting a client requires typing its name, and the built-in console client has no Delete.

## What was built

**Task 1 (dc06a6e): type picker, collapsed Advanced, labels, warnings**
- `AppTypePicker.tsx`:
  - Five cards built on native radios in a fieldset, each with a lucide icon, a title and a one-line description.
  - `APP_TYPES` holds each type's defaults and its redirect URI example.
  - `ClientForm.newClientValues(type)` replaces `NEW_CLIENT`.
- `ClientForm`:
  - The picker comes first in create mode. Switching type keeps the name and URLs and resets the type-specific settings.
  - Without the authorization code grant, the form hides redirect URIs, post-logout URIs, consent, PKCE, the ID token algorithm, back-channel logout, PAR, headless native, the home URLs and the MFA/organization policy. This is how M2M works. Edit mode uses the same rule.
  - "Advanced" is a disclosure button (`client-advanced-toggle`, `aria-expanded`). It holds application type, token format, ID token algorithm, introspection, resource indicators, back-channel logout, PAR, client kind and headless native. It opens on its own when the server reports an error on one of those fields.
  - Auth methods have human labels (for example "Client secret (HTTP Basic)"), with the raw value shown in a muted mono hint. Grant types have human labels, with their protocol values listed below.
  - A Native or SPA app switched to Confidential shows the `confidential-warning` callout ("A secret in a shipped app is not secret").
  - The Redirect URIs field shows an example for the chosen type (placeholder and hint). Server messages, such as a missing scheme, appear inline at the field.
  - New optional fields "App home page" (`client_uri`) and "Sign-in start URL" (`initiate_login_uri`). Empty means null, so the server validates the value or clears it.
  - `useFormState` and `useUnsavedChanges(isDirty && !pending)` are wired in, with `UnsavedChangesGuard` outside the form. The form has a single submit button.

**Task 2 (11ab024): Integration card, danger zone, console client, list**
- `IntegrationCard.tsx`:
  - Shows Issuer, Discovery URL, Client ID, the client secret (only when passed), one CopyField per redirect URI, and a `.env` snippet (`ANVILID_ISSUER`, `ANVILID_CLIENT_ID`, and `ANVILID_CLIENT_SECRET` only when the secret is present) with one Copy button.
  - The issuer and discovery URL come from `useTenantView`.
- Created page: the card receives the same component-state secret as `OneTimeSecret`. Dismissing the secret removes it from both places.
- Client page:
  - The read-only duplicate of the form is gone. A compact facts row remains (type, authentication, created by, created, updated), followed by the Integration card, the one Settings form, and a "Client secret" card.
  - The rotation dialog says the old secret stops working immediately.
  - Delete moved into `DangerZone` (confirm by typing the client name).
  - For `anvil-console` in the system tenant there is no danger zone; the page shows a "Built-in client" badge and a note instead.
- Clients list:
  - The name is the link, with the client ID in mono inside it.
  - A "Created by" column shows Admin, Dynamic registration or Metadata document. It keeps the `client-source-{id}` test id.
  - The Type and Authentication columns use the human labels.

**Task 3 (7cbe150): e2e**
- New `console-app-onboarding.spec.ts`:
  - The tenant view's issuer matches the discovery document.
  - On the new client page, Web is preselected, axe passes and there is no overflow at 390px.
  - For each of Web, SPA, Native, M2M and Agent: the form defaults, any hidden fields, creation, the stored values from the admin API, the Integration card values and Copy buttons, and how the secret is handled.
  - Native + Confidential and SPA + Confidential both show the warning.

  - A `javascript:` App home page is refused at the field; valid home URLs are stored.
  - List labels, the console client having no Delete, and the typed-name delete (wrong case stays disabled; Cancel keeps the client; 404 afterwards).
- `console.spec.ts`: the picker step and the Advanced toggle. The sample RP step now reads the form fields instead of the removed read-only card.
