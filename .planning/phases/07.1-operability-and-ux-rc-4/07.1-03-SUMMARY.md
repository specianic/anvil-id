# Phase 07.1 Plan 03: Console foundation (Specianic tokens, grouped nav, shared safety components) Summary

The console now uses the Specianic palette and font stacks with OS-driven dark mode. Navigation is a grouped sidebar built from TENANT_PAGES, with a Menu button below 768px. The header shows the admin's email: oidc.ts requests `profile email` and sets `loadUserInfo: true`. The later screen plans get one shared component each for typed-name danger zones, copy fields, unsaved-changes guards and slug fill.

## What was built

**Task 1 (ca50d8c): tokens, fonts, dark mode, lucide-react**
- `styles.css` maps the Specianic tokens onto the shadcn variables (hex values) in light and in `@media (prefers-color-scheme: dark)`:
  - canvas, surface, sunken, line, line-strong, ink, ink-muted, signal, signal-text, danger and success;
  - `--primary` is signal with `#0f0f10` foreground in both themes;
  - `--ring` and `--link` are signal-text;
  - `--radius: 2px`, and every `rounded-sm..xl` utility resolves to it.
- `@theme inline` declares `--font-sans` / `--font-mono` with the Specianic stacks and adds `color-link`, `color-success` and `color-destructive-foreground`. Body text uses `font-sans` and code uses `font-mono`. There is no @font-face and no CDN (07.1-10 wires the files).
- Card is square with a border and no shadow. Button and Badge use the 2px radius, and their link variants use `text-link`. Destructive variants use `text-destructive-foreground`. A destructive Alert renders a lucide `CircleAlert` unless the caller passes `icon`.

**Task 2 (6405255): grouped navigation, mobile menu, admin identity, switcher label**
- `TENANT_PAGES` gains `group` and `systemTenant` fields and an Overview entry first. It covers all 15 sections, including Password hash profiles, and is the only nav source: the `NAV` const in AppShell is gone. Helpers: `NAV_GROUPS`, `navGroupsFor(tenant)` and `pageAvailableIn(page, tenant)`.
- AppShell renders a sidebar (`nav[aria-label=Main]`, id `main-nav`) with an eyebrow `h2` for each group. The active link gets a signal-text left border and `aria-current="page"`.
- Below 768px a "Menu" button (`aria-expanded`, `aria-controls="main-nav"`) toggles the nav. Escape closes it and returns focus to the button, and following a link closes it. The skip link is still the first tab stop.
- The header shows `email ?? name ?? preferred_username ?? sub` (`data-testid="console-admin"`).
- Tenant switcher option labels: "System", "Default", or "<display name> (slug)". When the admin switches to the system tenant from a section it lacks, the console opens the Overview instead.
- `console.spec.ts` gains two steps. The first checks the admin email in the header, the five group headings and the Overview link. The second runs at 390px: menu button state, the keyboard open/Escape/focus return, link-follow closing the menu, and axe with the menu open.

**Task 3 (bd4d5f4): shared safety components**
- `DangerZone`: props `{ title, description, confirmText, actionLabel, onConfirm, pending, error? }`. It renders a bordered "Danger zone" section with a TriangleAlert icon. Its button opens a modal, and the destructive submit (Trash2 icon + verb) stays disabled until the typed text equals `confirmText` exactly.
- `CopyField`: props `{ label, value, mono? }`. It copies with `navigator.clipboard` and announces "Copied" in a polite `role=status`. When the clipboard is unavailable it selects the text and says so.
- `useUnsavedChanges(isDirty)` wraps `useBlocker({ shouldBlockFn, enableBeforeUnload, withResolver: true })`. It reads the latest dirty state through a ref. `UnsavedChangesGuard` renders "Leave without saving?" with "Stay" (focused first) and "Leave".
- `slugify(name)`: accents folded via NFKD plus ß/æ/œ/ø, other character runs become '-', ends trimmed, at most 63 characters. This matches anvil-core's `validate_slug`, `validate_org_slug` and `validate_connection_slug` syntax; the server enforces the minimum length. `useSlugFromName()` returns `{ slug, setSlug, onNameChange }` and stops following the name once the slug is edited. Clearing the slug field makes it follow the name again.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Danger fill text contrast in dark mode**
- **Found during:** Task 1
- **Issue:** shadcn's `text-white` on the dark danger colour (#f0695e) is about 3:1, which fails AA.
- **Fix:** Added `--destructive-foreground` (white in light, ink in dark) and used it in the Button and Badge destructive variants.
- **Commit:** ca50d8c

**2. [Rule 3 - Blocking] ConfirmDialog cannot gate its confirm button**
- **Found during:** Task 3
- **Issue:** ConfirmDialog has no way to disable confirm until the typed text matches, and its cancel label is fixed to "Cancel". It lives outside this plan's files.
- **Fix:** DangerZone and UnsavedChangesGuard use the `Modal` that ConfirmDialog.tsx already exports (same dialog primitive, focus handling and alertdialog role). ConfirmDialog is unchanged and not forked.
- **Commit:** bd4d5f4
