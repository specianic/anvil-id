# Phase 07.1 Plan 14: Consent account switch, organization non-member page, magic-link guidance Summary

**The consent screen now names the signed-in account and offers a flow-bound "Use another account". Organization non-members get an explanation page whose "Return to <app>" still sends the client the same `access_denied`. The org chooser no longer pre-selects anything, and a magic link opened in another browser explains itself on GET, before anything is consumed.**

## Performance

- **Duration:** about 100 min
- **Completed:** 2026-11-28
- **Tasks:** 3
- **Files modified:** 39 (1 created)

## Accomplishments

- **Consent (U-M15, U-L4).** `#consent-account` shows the session user's email (`ConsentService::account_email`). `#consent-switch-form` posts `choice=other` to the same bound action. `ConsentService::switch_account` runs the same binding, owner and single-use checks as Allow/Deny and stores nothing. The browser then goes to `AuthorizeService::sign_in_as_other`, the path the account chooser's `choose_account` now uses as well. Copy: offline_access reads "Stay signed in to <app>", with a note that the app keeps access until you remove it. Static provenance reads "Set up by the administrators of this sign-in service." The agent badge keeps its text and adds `#consent-agent-explain`. The error contract sentences are untouched (the verify grep is clean).
- **Non-member page (U-M14).** `active_org` returns `OrgStep::NotMember` for `ActiveOrg::Denied` on interactive requests. `/authorize` stores the request, and a resumed request keeps it. `AuthorizeOutcome::NotOrgMember` redirects to `/ui/select-organization/not-member?request=`. That page (200, no-store, flow-bound) shows the reason, the account, `#link-return-to-app` and `#org-not-member-other`. Return calls `deny_not_member`, which produces the same `error_response(params, not_a_member())` as before. A test compares the full sorted query with the `prompt=none` answer.
- **Org chooser (U-L6).** No `checked` attribute, and labels show display names.
- **Magic link (U-M8).** `link_page` reads the flow cookie and `Sec-Fetch-Site`. The page adds `#magic-link-other-browser`, `#magic-link-code-hint` (when the tenant emails codes) and `#link-login` labelled "Start signing in again here" (NavContext keeps `request=`). The login_code email (txt and html) says the link works only in the browser where sign-in started and the code works on any device.
- **Emails.** Every default HTML email uses Specianic colours: canvas `#fafaf9`, ink `#0f0f10`, ink-muted `#5c5a56`, an orange `#ff5a1f` button with ink text, and the copy-this-address link as an anchor in signal-text `#c2410c`. Variables are unchanged, and anvil-mail's template tests pass.
- **Locale.** `AppState::authorize_response` takes the page's locale, so error outcomes from consent, the chooser, the switcher and the non-member page render in the negotiated language. The three UI modules build their sign-in redirect through `NavContext`.

## New negative tests (for the security map; 07.1-11 owns scripts/check-security-tests.sh)

- `consent::consent_switch_account_requires_binding`: no CSRF, forged CSRF, no flow cookie, cross-site, another user's session give 403. `choice` together with `decision` gives 400. The session stays active and nothing is granted. After a real switch, the used page cannot answer again
- `org_switch::non_member_page_requires_binding`: missing or forged CSRF, no flow cookie and another user's session give 403. An unknown choice gives 400. The request is still stored and the bound page still answers
- `org_switch::non_member_page_without_session_or_refusal`: without a session the page sends you to sign in. A user who is not refused (a member) gets the flow_expired page with no buttons
- `org_switch::non_member_sees_why_and_return_to_app_is_the_same_access_denied`: the protocol result equals the direct refusal, and a second answer gives 400 with no redirect
- `org_claims::nonmember_organization_is_access_denied` (updated): `prompt=none` still returns access_denied directly, and the page never reveals the org's stored display name
- `consent::use_another_account_on_consent_asks_the_next_user_for_their_own_consent`: A's grant is never used for B, and A's session is revoked
- `flow_email_code::magic_link_in_another_browser_explains_before_any_action`: nothing is consumed or signed in on GET
- `ui::email_code::tests::link_browser_needs_the_cookie_or_a_navigation_that_would_carry_it` (unit)
