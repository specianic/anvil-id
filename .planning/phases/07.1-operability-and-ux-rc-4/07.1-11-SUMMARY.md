# Phase 07.1 Plan 11: Tenant YAML logos, organizations and client home URLs Summary

Tenant documents (version 1, new optional keys only) now carry logos for tenant, client and organization branding, client `client_uri` / `initiate_login_uri`, and an `organizations[]` section. Organizations come with their roles, connections, domain claims, default roles and branding. Every write goes through the owning services. A missing key changes nothing, even with `--prune`, and a document can never mark a domain verified.

## What was built

**Task 1 (15ce8c1): document model and JSON Schema**
- `LogoInput` has a custom wire form. `{file}` is refused with a message pointing to the CLI. The `Debug` output hides the base64 data.
- `logo` uses an absent/null/value tri-state (`double_option`) on `BrandingSection` and `OrgBrandingSection`.
- New fields and sections: client home URLs, plus `OrganizationSection` with nested roles, connections (reusing `ConnectionSection`), domains and branding. All of them use `deny_unknown_fields`.
- Schema additions:
  - `$defs`: `logo`, `organization`, `org_domain`, `org_branding` and `theme_tokens`
  - a SAML variant of `connection_config`
  - client home URLs
- Sync test `config_doc_new_keys_match_the_schema_and_the_model`.

**Task 2 (7092520): export, plan and apply**
- **Plan:**
  - Logos compare by SHA-256; inline data is hashed first.
  - An absent desired logo is not compared, and `null` counts as equal to "no stored logo".
  - `plan_organizations` diffs each listed org: head fields, then roles, connections (with secrets), domains and branding.
- **Validation (by path):**
  - org slug, display name and metadata; at most 20 default roles
  - org roles cannot carry `admin:*`
  - org connections: OIDC or SAML only; no SAML secret; one slug namespace with tenant connections and the other orgs
  - domains are normalised; routing needs a target from the same entry; turning off password sign-in needs routing
  - logo upload rules apply
  - the system tenant cannot have `organizations`
- **Checks against stored state:**
  - connection slug owned by the tenant or by another org
  - kind changes
  - secrets that must be provided
  - default roles that name no role
  - unknown logo hash, or a content type that differs from the stored one
  - creating or changing a SAML connection while the flag is off
- **Apply (`write_org`):** org → roles → connections (secret first) → domain claims (`OrgDomainService::add`, then the target and routing patch) → default roles → prune-only deletes (domains, connections, roles) → branding (put, then the logo via `set_logo` / `clear_logo`). Tenant and client branding only call `put` when tokens or CSS change, and the logo is applied separately.
- `ConfigService` gets `orgs: OrgService` and `domains: OrgDomainService`. It is wired in `admin/config.rs` (the `domain_txt` from `AppState`) and in the CLI (`HickoryTxtLookup` on the configured resolvers; never used to verify).
- The admin API flags these with their paths: `{file}` logo references, and `{env}` / `{file}` secrets on org connections.

**Task 3 (70e1996): CLI, docs, security map, OpenAPI**
- `resolve_logo_files`: `{file}` is resolved relative to the document. The size is checked through file metadata first, then capped by a bounded read, and the file is inlined as `{data}`.
- The org connection secret slot accepts the existing `{env}` / `{file}` references.
- CONFIG-YAML.md:
  - "does not contain" now lists only runtime data and domain verification
  - new sections: Logos (forms, 1 MiB HTTP limit, use the CLI for several inline logos), Client home URLs, and Organizations (replacing "Organizations are not part of the document")
  - updated secrets, pruning, ordering and limits text
- OpenAPI:
  - config plan `kind` / `key` descriptions
  - the 422 descriptions of createConnection, updateConnection, createOrganizationConnection and updateOrganizationConnection now say that enabling an incomplete connection, or one whose issuer fails discovery, is refused (07.1-09 note)
  - schema.d.ts regenerated; operation count unchanged
