<objective>
Build the single end-user flow navigation mechanism (U-H1 root cause) and use it everywhere a flow page links
onward: detours keep the app's authorization request, emailed recovery/verification links carry it, stale
requests fail on GET before credentials, and the "Signed in" page offers a way forward.

Purpose: every end-user dead end in the review has one root cause: the request id lives on the flow row
(`Flow.auth_request_id`) but links are rebuilt from the query string only at flow start. This plan is the
foundation the PRG (07.1-07), error/logout (07.1-08), account (07.1-12) and sign-in-screen (07.1-13) plans build on.
Output: `ui/nav.rs`, rewired call sites, emailed `request=`, `tests/flow_nav.rs`, nav.ftl (en/de).
</objective>

```rust
// crates/anvil-web/src/ui/nav.rs
pub(crate) enum UiPage { Login, Registration, Recovery, Verification, Account(AccountSection), SignOut }
pub(crate) enum AccountSection { /* one variant per existing /ui/account/* route */ }
pub(crate) struct LiveRequest { pub id: AuthRequestId, pub client_id: String, pub client_name: String }
pub(crate) struct NavContext { request: Option<LiveRequest>, return_to: Option<ReturnTarget> }
pub(crate) struct WayForward { pub primary: NavLink, pub secondary: Vec<NavLink> }
pub(crate) struct NavLink { pub href: String, pub label_key: &'static str, pub app_name: Option<String>, pub method_post: bool }
pub(crate) enum StaleRequest { Unknown }   // no reason detail (no oracle)
impl NavContext {
    pub(crate) async fn from_query(state: &AppState, tenant: &ResolvedTenant, raw: Option<&str>) -> Result<Self, StaleRequest>;
    pub(crate) async fn from_flow(state: &AppState, tenant: &ResolvedTenant, flow: FlowId) -> Self;
    pub(crate) fn none() -> Self;
    pub(crate) fn request(&self) -> Option<&LiveRequest>;
    pub(crate) fn url(&self, tenant: &ResolvedTenant, loc: &Locale, page: UiPage) -> String;
    pub(crate) fn links(&self, tenant: &ResolvedTenant, loc: &Locale, form_id: &str) -> PageLinks; // replaces links_for
    pub(crate) fn way_forward(&self, state: &AppState, tenant: &ResolvedTenant, loc: &Locale, signed_in: bool) -> WayForward;
}
```

session exists); else signed in -> account page (+ sign-out POST; + console link in the system tenant); else
tenant sign-in. 07.1-08 extends `way_forward` with the client's `initiate_login_uri`/`client_uri` (decision 1);
leave a clearly named single place (`fn app_home(&self) -> Option<NavLink>` returning None until then is NOT
allowed — no stubs; simply do not add it).
