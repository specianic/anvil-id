# Phase 07.1 Plan 09: Upstream connection enablement safety Summary

Enabling an upstream connection is refused server-side (422 with the field) until it is complete and, for generic OIDC, its issuer passes discovery through the SSRF-guarded upstream port. Incomplete rc.3 rows are hidden from sign-in. The console creates connections disabled, shows the redirect URI before saving, fills the slug from the name and guards unsaved edits.

## What was built

**Task 1 (db75d45), server rule, filter and negative tests**
- `ConnectionConfig::missing_for_enable(has_secret)` and `Connection::missing_for_enable()` / `is_offerable()` are the single definition of completeness. Fields are reported as API paths: `config.client_id`, `config.issuer`, `config.apple[.team_id|.key_id]`, OAuth2 endpoints, `config.mapping.subject`, the SAML entity id / SSO URL / certificates, and `secret`.
- `check_enable(config, has_secret, upstream)` refuses with the first missing field. For generic OIDC it then calls `UpstreamClient::metadata(issuer)`. Each failure maps to a fixed message on `config.issuer`: blocked, unreachable, HTTP status, too large, issuer mismatch, or unusable document. The message never contains the issuer, an address or anything fetched.
- `ConnectionService::create_as` / `update_as` run the check after static validation and the SAML flag check, before any storage write. The admin API and the CLI tenant YAML pass `UpstreamHttp` (CLI: built on the same `startup::outbound_client` as `serve`).
- `sign_in_connections(storage, tenant)` in core is now the one listing behind `upstream_buttons`. `confirmable` (link choices) uses `is_offerable`.
- YAML apply now sets a connection's secret before patching it, so one document can add a secret and enable the connection.

**Task 2 (6ba18de), console and e2e**
- ConnectionForm:
  - `enabled: false` by default, with the hint "Turn on after you registered the redirect URI at the provider."
  - Redirect URI preview (CopyField) above the save button, updating live with the slug.
  - The slug follows the display name until edited (preset slugs like `google` also follow).
  - `useFormState` + `useUnsavedChanges` + `UnsavedChangesGuard`; a typed secret counts as dirty.
- Connection page:
  - New Status card: Enable/Disable buttons, and the server's 422 reasons listed with field labels.
  - Redirect URI card warns (`redirect-uri-mismatch`) when the saved URI differs from the computed one.
  - Edit form no longer sends `enabled`.
- List page: Enabled/Disabled plus Incomplete badges (icon and text).
- e2e: `console-connection-safety.spec.ts` covers:
  - slug fill
  - disabled default and redirect URI before saving
  - dirty-form prompt with Stay
  - saved URI equals the preview
  - Enable without a secret shows "Client secret: a client secret is required ..."
  - no "Continue with" on `/ui/login`
  - list badges

  `console-connections.spec.ts` now enables the Google connection after creating it.
