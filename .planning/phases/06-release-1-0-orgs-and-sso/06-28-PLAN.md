<objective>
Gap closure for three sign-in items in deferred-items.md and the orchestrator decisions 1 and 4:
- (06-22) `OrgRepo::tenant_has_routing` ignores the SAML runtime flag, so a tenant whose only route is SAML with the flag off shows
  the email page and every address goes to the password step;
- (06-22) the brute-force lock and CAPTCHA pages (`posted_login_form`) render the combined form in routed tenants;
- (06-14) org JIT follows the tenant `upstream_registration`, so a B2B tenant with closed registration silently blocks org SSO
  sign-ups. Decision: JIT through an org-owned connection is allowed whatever the tenant's registration setting is (the admin
  explicitly configured the org connection); tenant-level connections keep following `upstream_registration`.

Purpose: identifier-first sign-in and org SSO behave consistently before the 1.0 prerelease; the docs stop listing these as limitations.
Output: port change on both backends, flow/web changes, linking rule, positive and negative tests, docs.
</objective>
