**Policy (pure).** `policy/return_to.rs`: `pub struct ReturnTarget(String)` (Debug redacts the token: it is a bearer value),
`pub fn parse_return_target(raw: &str) -> Option<ReturnTarget>` implementing the allowlist exactly (prefix `/ui/invitation?token=`,
then 1..=MAX_TOKEN_LEN chars of `[A-Za-z0-9_-]`, nothing else; reuse `service::org_invitation::MAX_TOKEN_LEN`, or move the constant
to the policy module and re-export it, one constant), `pub fn as_path(&self) -> &str`. Module doc: why an allowlist (the only
consumer is the invitation page; a general same-origin path rule is an open-redirect surface for no benefit), and that the web
layer prefixes the tenant's own UI origin. Register in `policy/mod.rs`. Unit tests = behaviour list.

**Flow state.** `LoginState.return_to_sealed: Option<String>`: the target sealed with the KEK, AAD/purpose bound to the flow id
(copy the SAML `identity_sealed` sealing helper; do not invent a second sealing scheme). `start_login(cx, auth_request, current,
return_to: Option<ReturnTarget>)`: store only when `auth_request` is None and the flow is a fresh login (not a step-up). The flow
restarts on expiry (`Restarted`) drop the target (documented; the user lands on the signed-in page).

**One continuation.** Introduce `pub enum Continue { Authorize(AuthRequestId), Return(ReturnTarget) }` and change
`FlowOutcome::SignedIn/SteppedUp.continue_to`, `UpstreamPrimary::SignedIn.continue_to` and `UpstreamOutcome::SignedIn.continue_to`
to `Option<Continue>`. A single private `fn continuation(&self, flow: &Flow, state: &LoginState) -> Option<Continue>` (auth request
first; else open the sealed target; a failed open -> None, logged at debug without the value) builds it at every construction site
(grep `continue_to:`; all 11 in flow.rs and the upstream path), so password, passkey, second factor, enrolment, email code/link,
upstream OIDC and SAML sign-ins all honour it.

**Sign-in after invitation registration.** Extract the body of `Effect::CreateSession` (switch_session, sessions().create,
record_login, audit LoginSucceeded) into a private helper used by the effect runner, and add `pub async fn
sign_in_registered_user(&self, cx, user: UserId, current: Option<&BrowserSession>) -> Result<NewSessionCookie, CoreError>` that calls
the same helper with `SessionAuth::Password` (no flow to delete; audit method `invitation_registration`). It refuses
(`InvalidRequest`) unless the user is active and email-verified. No second session-creation path.
